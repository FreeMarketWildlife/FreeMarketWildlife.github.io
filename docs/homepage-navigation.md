# Homepage and Games navigation

Local candidate only: publication requires the separately pending approval.

The homepage has three primary choices: Build a Business (`/build-a-business/`), Games (`/game/`), Blog (`/blog/`). Portfolio, Tanoshi and latest-post excerpts are absent from the homepage; their direct pages and the original blog post remain available. Blog generation no longer requires or recreates the removed excerpt region. An older layout can still explicitly opt in using its existing `blog:latest` markers.

On the protected Worker build, `account.js` loads `/api/account` with `cache: no-store`. A signed-in visitor sees My Workspace. `account-destination.js` accepts the server-selected primary only when its ID uniquely matches the authorized membership list and its path matches exactly. Paths must be plain root-relative page paths: no external authority, query, hash, encoding or traversal. Activation refreshes account state. An expired session returns to Build a Business; missing, conflicting or unassigned memberships open the existing chooser. Failed refresh clears stale chooser content and reports the load error. The static Pages build keeps the anonymous default.

No new primary-workspace setting is introduced. The existing server model selects the first assigned membership in row order; the owner receives the existing catalog order. Multiple memberships with a valid server primary use that primary. Multiple memberships without a valid primary use the chooser. Browser routing grants no access; all existing server-side membership checks remain in force.

`scripts/build_game_hub.mjs` builds `/game/index.html` from the existing accepted `games/index.html` listing and checks it against `games/catalog.json`. It keeps all six listed titles and links to the existing `/games/<id>/` runtimes, styles and thumbnails. The six hidden catalog flags remain unchanged. Run it after an accepted listing change, then update the one affected legacy listing hash in the games release manifest if needed. `--check` rejects stale output.

The main Worker redirects `/game` and the old `/portfolio/critz` hub to `/game/`. The games Worker redirects only exact `/games` and `/portfolio/critz/games` hub URLs, including their slash/index forms. It preserves nested game URLs and existing build/Kingdom redirects. Static legacy pages also provide canonical/meta redirects with an accessible fallback link or retained cards. Public portfolio discovery calls the hub Games; individual Critz game names, lore, workspace IDs and storage keys remain intact.

Both asset packagers include the new `game/` directory. The main Worker still excludes game runtimes; its page references the separately hosted `/games/*` files. No Worker route configuration, bindings, APIs, credentials, database schema or membership rules change.

Verification: `node tests/test_home_routes.mjs`, `node tests/test_blog_publishing.mjs`, `node scripts/build_blog.mjs --check`, `node scripts/build_game_hub.mjs --check`, `python3 scripts/check_site.py`, `python3 services/games/verify-release.py`, `npm test --prefix services/workspace-auth`, and the Worker dry-run. It checks widths 1440, 390 and 320, keyboard access, actual local blog content, primary/fallback/session-change cases, static redirects and direct legacy pages. HTTP redirects are separately checked against the actual Worker functions.
