# One world, player mode and author tools

The local app has one current validated map, owned by `createWorldSession`. Normal `index.html` is for playing. It contains no Edit button or editor links, and the author tools are not loaded by the player snapshot loader. The developer author entry is `editor.html`, which redirects into that same app with `?author=1&mode=edit`, preserving QA and shared-map state. The editor mounts in a scoped panel; it does not create another game iframe, switch the equipped build to Creative, or use a separate physics implementation.

Edit pauses/cancels runtime input. Returning to Play without a map transaction preserves the existing simulation and camera. A changed map starts a new throw using the current build; the app announces that reset. The canonical editable map is the source for gameplay terrain and world art. Editor drafts, validation, Undo, import/reset and read-only snapshots remain supported.

`author=1` is a local authoring convenience, **not authentication or access control**. Anyone who receives an author-capable public build could request that URL. No credentials or security grants were added. The hosted package includes `editor.html`, its template/styles and lazy modules. The entry also accepts Sites’ canonical `/editor` path, preserving the same query and snapshot without a redirect loop. `editor.html?qa=1` enters the same app at `index.html?qa=1&author=1&mode=edit`. Normal player entry has no Edit button or link. This is an explicit developer workflow, **not authenticated owner-only access**: anyone with the route can edit their own browser-local map. Those edits cannot modify another player’s map or publish the canonical default. No credentials, access grants or shared remote map-writing service were added. Publication still uses the existing authorized Site owner workflow.

Player map links use `index.html#map=…`. The lightweight `world-link.js` loader imports only the data codec/model, selects a validated read-only snapshot in the same world session, and never saves it. Clearing the link restores the previous local map or unsaved draft. A later hash wins over slower decoding/guards. The app guards pending space rewards immediately before selection/restoration, applies accepted revisions to its existing game path, and retries a blocked requested link after collection. Author mode handles its own editing/history hash flow instead of attaching a second player link handler.

Startup reads/migration occur in memory without rewriting saved map bytes. Explicit author edits can save the map; Adventure currency and owned equipment are separate. QA uses the existing session-only map store. If another tab changed the saved map after this app read it, `world.save()` refuses to overwrite those bytes. The current draft remains available to play/export; reload only after exporting anything that should be kept. Shared snapshots cannot save until the author explicitly chooses an editable copy.

Node tests cover actual editor Save/Play handlers, shared-map races, QA/read-only saves, no-startup writes, optimistic conflicts, simulation reuse, real shared-map fixtures and old link formats. Native acceptance still must verify lazy tool mounting, scoped styling/focus, desktop/phone switching, map edit/save/Undo/reload, shared/player links, and launcher/camera/audio behavior. Test success does not certify those UI observations.
